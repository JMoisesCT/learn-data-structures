Hash table

An array of buckets and a hash function that turns each key into the number of its bucket. That way, finding, inserting and removing cost O(1) on average: you go straight to the right place instead of walking through everything.

The idea: from key to index

Think of gym lockers numbered from 0 to 6. If the rule is "your locker is the remainder of dividing your member number by 7", you never have to check the lockers one by one: you do the math and go straight there.

That's a hash table. The rule is the hash function; the array of lockers is the buckets, and how many there are is called m.

int index = key % m;   // 15 % 7 = 1  →  bucket 1

The problem: with infinitely many keys and only m buckets, sooner or later two keys land in the same one. That's a collision, and half of this lesson is about how to resolve them.

Collisions with chaining

The most common solution: each bucket keeps a pointer to a linked list with all the keys that landed there. insert puts the new node at the front, like insertAtFront in the linked list: O(1), collision or not.

find and remove only walk the list of one bucket: if the lists are short, it's almost instant. This insert doesn't check for duplicates; std::unordered_set does (it's an exercise at the end).

Collisions with open addressing

No lists: the keys live in the array and, if the cell is taken, another one is tried on attempt i = 0, 1, 2… according to the probing. Try it: with each strategy, insert 14 (it lands in 0); then remove 7 and find 42.

With quadratic probing, inserting 14 fails even though 2 cells are still free. Why?

Load factor and rehash

What rules is the load factor α = n / m. With chaining it's the average length of the lists: finding costs O(1 + α). With open addressing it doesn't go over 1, and near 1 the attempts shoot up.

If α goes over a limit (1.0 in std::unordered_map), there's a rehash into a table with about twice the buckets (the next prime after 2 · m). All keys change bucket: key % m depends on m.

Rehash costs O(n). Why do we still say inserting is O(1)?

  • Dictionaries and sets: counting words, removing duplicates, knowing whether you've already seen something (std::unordered_set).
  • Caches: keeping results already computed (memoization), web page and DNS caches.

In C++, std::unordered_map and std::unordered_set are tables with chaining (look at bucket_count() and load_factor()). For keys in order, std::map (a tree, O(log n)).
