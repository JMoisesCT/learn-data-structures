Lambdas in C++

An unnamed function written right where it is used. It is not a data structure, but it is how you tell std::sort how to sort or std::count_if what to count.

An unnamed function

[captures](parameters) -> type { body }

Brackets: which outside variables it uses. Parentheses: what it receives. Body: what it does. The return type is rarely written: it is deduced from return.

Writing the lambda creates a function object (that's why it is stored with auto), but the body doesn't run yet. It runs only when called, like any function: with its own frame on the stack.

Capturing by value: [factor]

A lambda doesn't see the variables of the function where it is written, unless it captures them. With [factor] it keeps a copy at the moment it is created: if you change factor afterwards, the lambda doesn't notice. [=] copies everything it uses.

Capturing by reference: [&total]

With & the lambda doesn't take a copy: it keeps where the original variable is (the arrow). That way it can modify it, like here, where each call adds to total. [&] captures everything it uses this way.

Nested lambdas: one inside another

A lambda's body can define and call another one. square is a local variable of sumSquares: it is created every time that one runs and destroyed when it finishes. Each call opens its own frame on the stack.

Nested lambdas: one that makes others

A lambda can return another lambda. makeAdder(10) makes a function that adds 10, and makeAdder(3) a different one that adds 3: each one remembers its own b, even though the frame where it was created no longer exists.

Practical use: counting with std::count_if

The algorithms in <algorithm> know how to traverse; the lambda tells them what to look for. count_if calls the lambda with each element and counts how many times it returned true. It is written right there, as an argument, and it captures limit to compare against it.

Practical use: searching with std::find_if

find_if asks the lambda element by element and stops at the first one that matches. It returns an iterator to that element, or numbers.end() (the position after the last one) if none matches.

Practical use: sorting with your criterion

std::sort sorts from smallest to largest, but if you pass it a lambda comp(a, b) that answers «does a go before b?», it sorts with whatever criterion you want. The algorithm doesn't change: only the question does.

Captures, cost and where you will use them

CaptureWhat the lambda keeps
[]Nothing: it only uses its parameters.
[x] / [=]A copy of x / of everything it uses. It works even if the variable dies before the lambda.
[&x] / [&]A reference: it can modify the original and copies nothing big. Only if the variable lives longer than the lambda.
[x, &y]Mixed: a copy of x, a reference to y.
[x]() mutableA copy that the lambda can modify.
[](auto a, auto b)Generic lambda (C++14): it works for any type.
With a lambdaTimeYou will see it in
std::count_if, std::for_eachO(n)Traversals: one call per element
std::find_ifO(n)Searches: it stops at the first one that matches
std::sort(…, comp)O(n log n)Sorting: about n·log n comparisons
std::priority_queue with decltype(comp)O(log n)Heap: a min-heap with x > y
  • Creating a lambda is O(1): it is an object that only stores its captures. Calling it costs the same as a normal function (the compiler usually inlines it).
  • Store it with auto. std::function<int(int)> stores «anything that can be called» (for example, a recursive lambda), but it is a little slower.
  • Prefer short lambdas, and be careful with [&] in a lambda that is returned or stored for later: references to local variables are left dangling.
