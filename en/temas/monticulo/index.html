Heap and heapsort

A binary tree stored in an array with the largest (max-heap) or the smallest (min-heap) always at the root. Includes heapsort.

A tree inside an array

A heap is a complete binary tree: every level is full except, maybe, the last one, which fills from left to right. Thanks to that it needs no pointers: it's stored level by level in a vector, and the positions of the parent and the children come out of a formula.

int parent = (i - 1) / 2;int left   = 2 * i + 1;int right  = 2 * i + 2;

Try it: tap any node (or cell) and see where its parent and its children are. This is the array { 3, 10, 1, 8, 6, 4 } from main().

The heap rule

Besides the shape, there's an order rule between each parent and its children:

  • Max-heap: each parent is ≥ its children, so the maximum ends up in v[0].
  • Min-heap: each parent is ≤ its children, so the minimum ends up in v[0].

There's no order at all between siblings. Think of a hospital emergency room: it doesn't matter who arrived first, but who is the most serious, and that has to be known instantly.

maxHeapify: sinking a node

The key piece. If i's subtrees are already max-heaps but v[i] is too small, maxHeapify swaps it with its largest child and calls itself one level down (above the drawing you'll see the calls in progress). It goes down at most the height of the tree: O(log n).

Building a max-heap: buildMaxHeap

maxHeapify is called on each node that has children, from the bottom up: from n / 2 - 1 to the root. That way, when a node's turn comes, its subtrees are already fixed.

Building a min-heap: buildMinHeap

The same algorithm with the comparison reversed: minHeapify brings up the smallest. With the same array, compare the result with the max-heap from the previous step, { 10, 8, 4, 3, 6, 1 }.

Using it: insert, peek and extract

A heap is a priority queue (the type picks max or min). insert adds a leaf that rises; extract takes out the root and sinks the last leaf: O(log n).

maximum / minimum only read v[0]: O(1). With an empty heap they return INT_MIN / INT_MAX, just like extract.

Heapsort: sorting with a max-heap

Taking out the root of a max-heap over and over gives the values from largest to smallest. heapSort does it in the same array.

Complexity and where it's used

FunctionTimeWhy
maximum / minimumO(1)It's always in v[0].
maxHeapify / minHeapifyO(log n)It goes down at most the height of the tree, which is log₂ n.
insertMax / insertMinO(log n)It rises at most the height of the tree.
extractMax / extractMinO(log n)One call to heapify from the root.
buildMaxHeap / buildMinHeapO(n)Most nodes are near the bottom and barely move.
Searching for any valueO(n)There's no order between siblings or between branches.
heapSortO(n log n)n extractions of O(log n). O(1) extra memory. It isn't stable.
A heap isn't sorted: it only guarantees that the root is the maximum (or the minimum). That's exactly what makes it fast.
  • Priority queues: task schedulers, events in a simulation, emergency rooms.
  • Graphs: Dijkstra (shortest paths) and Prim (minimum spanning tree) use a min-heap.
  • The k largest or smallest of a lot of data without sorting it all, and the running median with two heaps.

In real C++: std::priority_queue<int> is a max-heap; for a min-heap, std::priority_queue<int, std::vector<int>, std::greater<int>>. There are also std::make_heap, std::push_heap, std::pop_heap and std::sort_heap in <algorithm>.
