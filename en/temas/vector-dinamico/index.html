Dynamic array

An array that grows on its own. It stores the elements next to each other in memory, so reaching any position is immediate. It is the idea behind std::vector, and you will see what each of its operations does inside.

Slots next to each other

It keeps three things: data, a pointer to the block reserved with new; size, how many elements there are (▲ size marks the first free slot); and capacity, how many slots the block has (the dashed ones are free).

Because the slots are contiguous, the address of data[i] comes from arithmetic: start + i × 4 bytes. There is nothing to walk through: that is why get(i) is O(1).

If data starts at 0x1000 and an int takes 4 bytes, where is data[5]?

pushBack: write into the next slot

While size < capacity, adding at the end is just writing into data[size] and adding 1: O(1).

When it fills up, a block of memory can't be stretched (what comes after it may belong to another variable). So resize reserves a block twice as big somewhere else, copies everything, frees the old one with delete[] and moves the pointer.

The array has size = 4 and capacity = 4. How many values does the next pushBack copy?

Why grow to double and not one at a time?

Each resize copies everything. Compare the two strategies: each bar is what one call cost.

When doubling, the expensive copies get rarer and rarer: after copying n elements there are n free slots left. For n elements it does fewer than 2n writes: on average, each pushBack is O(1). That is its amortized cost.

Starting with capacity 2 and doubling, how many times does it resize when adding 1000 elements?

insert(pos, value): open a gap

The slots can't be "pulled apart" to fit a new one in the middle. Everything from pos to the end has to shift one place to the right, and only then is the value written. The more elements to its right, the more expensive: O(n).

Why does the for loop in insert go from right to left (i--)?

removeAt(pos): close the gap

The reverse of insert: each element to the right of pos shifts to the left, and the first one overwrites the one being removed. At the end, size goes down by 1. The memory is not freed: the last slot is left as garbage and the capacity doesn't change.

In an array with n elements, how many does removeAt(0) shift?

find(value): look slot by slot

Knowing the position gives immediate access, but knowing the value doesn't tell you where it is. If the array isn't sorted, you have to check from the beginning until you find it: O(n). If it isn't there, it returns -1.

Complexity and when to use it

OperationIn std::vectorTimeWhy
get(i)v[i], v.at(i)O(1)The address is computed with arithmetic.
pushBackv.push_back(x)O(1) amortizedThere's almost always room; sometimes everything is copied.
insert(pos, x)v.insert(v.begin() + pos, x)O(n)Everything from pos on shifts to the right.
removeAt(pos)v.erase(v.begin() + pos)O(n)They shift to the left to close the gap.
find(x)std::find(v.begin(), v.end(), x)O(n)Slot by slot (if it isn't sorted).
getSize() / getCapacity()v.size() / v.capacity()O(1)They just read a variable.
If you know in advance how many elements you will store, v.reserve(n) reserves the capacity in one go and avoids every copy made by resize.
  • It's the default structure in C++: when in doubt, use std::vector.
  • Ideal when you access by position and almost always add or remove at the end. Also, since the data is together, the processor reads it very fast (cache).
  • Avoid it if you do many insertions or removals at the start or in the middle: consider a linked list or std::deque.
  • Careful: after a resize, pointers or references to old elements are left pointing to the freed block.
