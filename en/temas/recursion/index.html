Recursion

A recursive function calls itself with a smaller problem until it reaches one that answers itself. That is how trees and heaps are traversed: heapify, the binary tree traversals and merge sort all use it.

A function that calls itself

The base case is answered without a call (a single digit). The recursive case calls itself with something smaller: n / 10 removes its last digit, n % 10.

Each call opens its own frame on the stack, with its own n. When the base case is reached, the answers go back up and each frame finishes its sum.

Does the work go before or after the call?

Whatever goes before the call is done on the way down; whatever goes after it, on the way back and in reverse order. These two functions only move the cout, and that is why they print the digits in opposite orders.

Carrying the result down

Instead of waiting for the answer to finish a calculation, reverseDigits passes the partial result as a parameter: accumulated grows on the way down and, at the base case, it is already the answer. On the way back nobody touches it. When the recursive call is the last thing done, it is called tail recursion.

Base conversion: the remainders are the digits

Divide n by the base: the remainder is the last digit and the quotient holds the ones in front. Each frame appends its digit after what the call below returns, so they end up in order.

DIGITS is the text "0123456789ABCDEF": at position k is the symbol worth k (DIGITS[10] is the char 'A'). std::string(1, c) builds a string with 1 copy of the char c, because toBase returns std::string.

Two base cases: palindromes

A palindrome reads the same forwards and backwards. isPalindrome compares the letters at the ends, i and j; if they are equal, it asks the same question about the text inside. It has two base cases: i and j crossed (everything matched) or there is a mismatch.

Fast power: halving the exponent

With a for loop, 210 needs 9 multiplications. But 210 = (25)² and 25 = (22)² × 2: if each call cuts the exponent in half, there are only about log₂ n calls. The key is to compute half once and multiply it by itself.

Fibonacci: when recursion repeats work

fibonacci(n) makes two calls, so they form a tree, and the branches ask for the same thing many times (in red): it is O(2ⁿ).

With memory (memo), each value is computed once; when it is asked for again, it is returned right away and that branch is pruned: O(n).

Complexity and when to use recursion

FunctionTimeStackWhy
digitSum, print…, reverseDigitsO(d)O(d)One call per digit (d ≈ log₁₀ n).
toBaseO(logb n)O(logb n)Each call divides n by the base.
isPalindromeO(n)O(n)One call per pair of letters.
powerO(log e)O(log e)The exponent is halved.
fibonacciO(2ⁿ)O(n)It repeats work: n = 40 makes more than 300 million calls.
fibonacciMemoO(n)O(n)Each value is computed once.
  • The stack costs too: each call in progress takes up a frame. The stack is only a few MB, so a recursion one million levels deep overflows even if it is O(n).
  • Each call must get closer to the base case (n / 10, exponent / 2, i + 1 and j - 1). Otherwise, it never ends.
  • Use it when the problem splits into smaller identical problems: trees, heaps, divide and conquer (merge sort, binary search), backtracking.
  • Prefer a loop for very long simple traversals, and add memory when branches repeat calculations.

Practice

  1. Write a recursive int countDigits(int n). What is its base case?
  2. Write bool containsDigit(int n, int d), which says whether the digit d appears in n. How many base cases does it need?
  3. Do the inverse of toBase: int toDecimal(const std::string& digits, int base). Hint: the value of "1101" is toDecimal("110") * 2 + 1.
  4. Write Euclid's greatest common divisor: gcd(a, b) = a if b == 0, and otherwise gcd(b, a % b). Is it tail recursion?
  5. Change power so that it computes baseexponent % m without overflowing (apply % m after each multiplication).
  6. Count the calls of fibonacci(n) for n = 10, 20 and 30 with a global counter. How much does it grow each time n goes up by 1?
