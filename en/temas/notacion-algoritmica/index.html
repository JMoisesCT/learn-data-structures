Algorithmic notation (Big-O)

The language for comparing algorithms: it doesn't measure seconds, it tells how the work grows when the data grows.

Count steps, not seconds

Counting steps (comparing, adding, reading a cell) doesn't depend on the computer, only on the algorithm and on the input size n. Big O notation answers: if n grows, how do the steps grow? Move n and compare.

With n² steps, if n goes from 1000 to 2000, how many steps does it take?

O(1): always the same

Reading data[i] in an array is one step, whether there are 5 elements or 5 million: the cell's address is computed with a calculation. That is called constant time, O(1).

In the program, each function does steps++ on every basic operation. Each steps++ drops a dot under the cell it touched, and each run leaves a point on the chart on the right. Run it with several different n.

A function always takes 3 steps, no matter what n is. What is its complexity?

O(n): one iteration per element

To add up an array there is no choice but to look at each element once. A for loop of n iterations with fixed work inside takes n steps: with twice the data, twice the steps. It is linear time, O(n). On the chart, the points form a straight line.

A function walks through the array twice in a row: first to find the maximum and then to find the minimum. What is its complexity?

O(n²): everyone against everyone

To know whether there are duplicates without sorting, you compare every pair: a for loop inside another. That is n·(n − 1)/2 pairs (one cell per pair in the table), almost n²/2: with twice the data, four times the work. It is O(n²).

Also try duplicate at the start: it finishes right away. That is the best case; when we say «it is O(n²)» we usually mean the worst case, the one with no duplicates at all.

hasDuplicates makes n·(n − 1)/2 = n²/2 − n/2 comparisons. Why do we say it is O(n²) and not O(n²/2)?

O(log n): split in half

If the data is sorted, binary search looks at the middle one and discards the half that cannot contain the target, and repeats. n can be split in half about log₂ n times until it reaches 1.

Like guessing a number from 1 to 100 with «higher» or «lower» hints: 7 questions are enough. With twice the data, one more iteration. It is O(log n), almost as good as O(1).

O(n log n): loops that multiply

A loop inside another multiplies their costs. countPresent does n binary searches of about log n steps: n columns of dots of height log n, n · log n in total.

It is the complexity of the good sorting algorithms, such as heapsort or merge sort: a little more than O(n), far less than O(n²).

A for loop of n iterations has another for loop of n iterations inside. What if the inner one always had only 10 iterations?

The rules: keep what grows fastest

A real algorithm almost never takes exactly n² steps: it takes something like 3n² + 5n + 20. Big-O keeps the fastest-growing term and drops its constant, because when n is large the rest goes unnoticed. Move n:

The rules: constants are dropped (O(3n) = O(n)), the largest term stays (O(n² + n) = O(n²)), steps one after another add up (O(n + n) = O(n)) and nested ones multiply (O(n · n) = O(n²)).

  • Big-O talks about how the work grows, not exactly how long it takes: with a small n, a simple O(n²) can beat a complicated O(n log n).
  • The worst case is given almost always, because it is a guarantee. Sometimes people talk about the average case (the hash table is O(1) on average) or the amortized cost (appending to the end of a vector).
  • The same goes for memory: an algorithm that makes a copy of the array uses O(n) extra memory.
  • To be precise: O is an upper bound («it doesn't grow faster than»). Ω is the lower bound and Θ, both at once. In practice, when someone says «it is O(n)», they almost always mean Θ(n).

Practice

  1. Write int maximum(const int data[], int n) with its steps counter. What is its complexity? Check it by adding it to the table in main().
  2. What is the complexity of this loop? for (int i = 1; i < n; i *= 2). And if it had a for (int j = 0; j < n; j++) inside?
  3. Change the inner loop of hasDuplicates so that it starts at j = 0 (skipping j == i). How many comparisons does it make now? Does its Big-O change?
  4. Write a version of fibonacci with a loop that keeps the last two values. Count its steps for n = 25 and compare them with the 242,785 of the recursive one.
  5. If you sort the array first (O(n log n)) and then compare only neighbors (O(n)), what is the complexity of hasDuplicates?
