Elementary sorting

Five ways to sort an array in place, without another array: by comparing pairs of values and moving them. They're short and easy to write; you'll see how much work each one does and when it's worth using.

Sorted = every neighbor in order

Each bar is a value of v: its height is the number. An array is sorted if every pair of neighbors is in order (v[i − 1] ≤ v[i]); isSorted checks it with n − 1 comparisons.

All the algorithms in this lesson do only two things: compare two values and move them (with swap or by shifting them). Counting comparisons and moves is how we'll measure how much they work.

exchangeSort: compare with everything after it

The most direct one: for each position i, it compares v[i] with every v[j] after it and, if v[j] is smaller, swaps them. When the round ends, v[i] holds the smallest of what was left and stays in place (green).

bubbleSort: neighbors out of order swap

It only compares neighbors (v[j] and v[j + 1]). In each pass the largest one moves forward like a bubble up to the end, where it stays fixed. If a whole pass swaps nothing, swapped stays false and the break ends it early.

selectionSort: find the minimum and put it at the start

In each round, the minIndex pointer walks what's left to sort and just notes where the smallest is. Only at the end of the round does it make a single swap to bring it to v[i]. It compares as much as exchange sort, but it moves far less.

insertionSort: slip each card into its place

Like sorting cards in your hand. The left part (v[0..i − 1]) is already sorted relative to each other; v[i] goes up as the key, the ones larger than it shift to the right (one write each, not a swap) and the key drops into the gap.

Stability: do equal values keep their order?

A sort is stable if two equal values end up in the same order they were in. With plain numbers you can't tell, but you can when sorting records: if you sort students by grade, the ones that tie stay, for example, in alphabetical order.

The two 4s are marked a and b. The ones that swap distant values can move one past the other; the ones that only move neighbors never cross two equal values.

shellSort: insertion sort with gaps

In insertion sort, a small value at the end travels one slot at a time. Shell sort first sorts the values that are gap apart (each color is a group), which travel far in a single step, and it ends with gap = 1 on an almost sorted array.

Complexity and when to use each one

AlgorithmBest caseAverageWorst caseExtra memoryStable
exchangeSortO(n²)O(n²)O(n²)O(1)No
bubbleSortO(n)O(n²)O(n²)O(1)Yes
selectionSortO(n²)O(n²)O(n²)O(1)No
insertionSortO(n)O(n²)O(n²)O(1)Yes
shellSort (gaps n/2, n/4…)O(n log n)depends on the gapsO(n²)O(1)No
  • Insertion sort is the best of the quadratic ones: very fast with small or almost sorted arrays. That's why std::sort uses it for the small pieces.
  • Selection sort makes at most n − 1 swaps: useful if writing is much more expensive than comparing.
  • Bubble and exchange sort are mostly for teaching: they're almost never the best option.
  • Shell sort uses no extra memory and is easy to write; with good gaps (Ciura's 1, 4, 10, 23, 57…) it competes with the fast ones on medium-sized arrays.
  • In C++ use std::sort (fast, not stable) or std::stable_sort (stable), from <algorithm>.
  • For large arrays you need to go down from O(n²) to O(n log n): heapsort (in Heap), and merge sort and quicksort.

Practice

  1. Add comparison and swap counters to each function and compare the numbers with the ones from the race.
  2. Make bubbleSort remember the position of the last swap of each pass: from there on it's already sorted, so the next pass can end earlier.
  3. Write cocktailSort: a bubble sort that goes forward (carries the largest to the end) and back (carries the smallest to the start).
  4. Change shellSort's gaps to the sequence 1, 4, 13, 40… (gap = 3 · gap + 1) and compare the comparisons with n = 1000.
  5. What happens if in insertionSort you change v[j] > key to v[j] >= key? It still sorts, but is it still stable?
