Notación algorítmica (Big-O)

Antes de comparar estructuras de datos necesitamos un idioma para decir qué tan rápido es algo. La notación O grande no mide segundos: dice cómo crece el trabajo cuando los datos crecen. Vas a ver cada clase contar sus pasos, punto por punto.

Contar pasos, no segundos

Si cronometras un programa, el resultado depende de tu computadora, del compilador y de qué más está corriendo. En cambio, el número de pasos (operaciones básicas: una comparación, una suma, leer una casilla) depende solo del algoritmo y del tamaño de la entrada, que llamamos n.

La notación O responde una pregunta: si n crece, ¿cómo crecen los pasos? Imagina que buscas a un amigo en un estadio. Si sabes su asiento, vas directo: O(1). Si recorres fila por fila, el doble de gente es el doble de trabajo: O(n). Si cada persona saluda a todas las demás, el doble de gente es el cuádruple de saludos: O(n²).

Mueve n o pulsa ▶ Ver crecer n: con números chicos todas se parecen, pero cuando n crece se separan muchísimo.

Un algoritmo hace n² pasos. Si n pasa de 1000 a 2000, ¿cuántos pasos hace ahora?

O(1): siempre lo mismo

Leer datos[i] en un arreglo es un paso, haya 5 elementos o 5 millones: la dirección de la casilla se calcula con una cuenta. A eso se le llama tiempo constante, O(1).

En el programa, cada función hace pasos++ en cada operación básica. Cada pasos++ deja caer un punto bajo la casilla que tocó, y cada ejecución deja un punto en la gráfica de la derecha. Ejecútala con varios n distintos.

Una función hace siempre 3 pasos, sin importar n. ¿Qué complejidad tiene?

O(n): una vuelta por elemento

Para sumar un arreglo no queda otra que mirar cada elemento una vez. Un for de n vueltas con trabajo fijo adentro hace n pasos: con el doble de datos, el doble de pasos. Es tiempo lineal, O(n). En la gráfica, los puntos forman una recta.

Una función recorre el arreglo dos veces seguidas: primero para buscar el máximo y después para buscar el mínimo. ¿Qué complejidad tiene?

O(n²): todos contra todos

Para saber si hay repetidos sin ordenar, se compara cada par de elementos: un for dentro de otro. Con n elementos hay n·(n − 1)/2 pares; la tabla de la animación tiene una casilla por par y se va llenando. Eso es casi n²/2: con el doble de datos, cuatro veces más trabajo. Es tiempo cuadrático, O(n²).

Prueba también repetido al inicio: termina enseguida. Es el mejor caso; cuando decimos «es O(n²)» solemos hablar del peor caso, el que no tiene ningún repetido.

hayRepetidos hace n·(n − 1)/2 = n²/2 − n/2 comparaciones. ¿Por qué decimos que es O(n²) y no O(n²/2)?

O(log n): partir a la mitad

Si los datos están ordenados, la búsqueda binaria mira el del medio y descarta la mitad que no puede tener al objetivo. Luego repite con la mitad que queda. ¿Cuántas veces se puede partir n a la mitad hasta llegar a 1? Unas log₂ n veces.

Es como el juego de adivinar un número del 1 al 100 con pistas «mayor» o «menor»: en 7 preguntas como máximo lo adivinas. Con el doble de datos, solo hace falta una vuelta más. Es tiempo logarítmico, O(log n), y casi tan bueno como O(1).

¿Cuántas vueltas da, como mucho, la búsqueda binaria en un arreglo ordenado de un millón de elementos?

O(n log n): ciclos que se multiplican

Cuando un ciclo está dentro de otro, sus costos se multiplican. contarPresentes hace n búsquedas binarias, y cada una cuesta unos log n pasos: en total, n · log n. Mira cómo cada consulta junta una columna de puntos: n columnas de altura log n.

Es la complejidad de los buenos algoritmos de ordenamiento, como el heapsort o el merge sort: un poco más que O(n), muchísimo menos que O(n²).

Un for de n vueltas tiene adentro otro for de n vueltas. ¿Y si el de adentro fuera de solo 10 vueltas, siempre?

Las reglas: quedarse con lo que más crece

Un algoritmo real casi nunca hace exactamente n² pasos: hace algo como 3n² + 5n + 20. Big-O se queda con el término que más crece y le quita la constante, porque cuando n es grande lo demás no se nota. Mueve n:

Resumen de las reglas: se quitan las constantes (O(3n) = O(n)), se quedan con el término mayor (O(n² + n) = O(n²)), los pasos seguidos se suman (un ciclo y luego otro: O(n + n) = O(n)) y los anidados se multiplican (un ciclo dentro de otro: O(n · n) = O(n²)).

¿Y en tiempo real?

  • Big-O habla de cómo crece el trabajo, no de cuánto tarda exactamente: con n chico, un O(n²) sencillo puede ganarle a un O(n log n) complicado.
  • Casi siempre se da el peor caso, porque es una garantía. A veces se habla del caso promedio (la tabla hash es O(1) en promedio) o del costo amortizado (agregar al final de un vector).
  • Lo mismo vale para la memoria: un algoritmo que crea una copia del arreglo usa O(n) de memoria extra.
  • Para ser precisos: O es una cota superior («no crece más rápido que»). Ω es la cota inferior y Θ, las dos a la vez. En la práctica, cuando alguien dice «es O(n)», casi siempre quiere decir Θ(n).
