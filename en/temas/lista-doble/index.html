Doubly linked list

Each node knows who comes after it and also who comes before it. It is the idea behind std::list.

Two pointers per node, and a list with two ends

Like the linked list, but each node also stores prev, and the list stores head and tail. It's like a train: from any car you can move to the one in front or the one behind.

Reaching a position is still O(n), but nodeAt picks the nearest end: if pos is in the second half, it walks backward from the tail. At most n / 2 jumps.

In a list of 1000 nodes, how many jumps does nodeAt(990) make?

Inserting at both ends: O(1)

At the front, the new node points to the head and the head points back to the new node. At the back the same happens with tail: nothing has to be walked to reach the last one. If the list was empty, the new node is head and tail.

insertAt: four pointers

nodeAt(pos) gives the node that is at pos right now, and its prev comes for free. The new node slips in between them by changing four pointers: the new node's two and one of each neighbor. The ends reuse insertAtFront and insertAtBack.

remove: the node knows who comes before

In the singly linked list, to take a node out you had to find its previous node. Here each node stores it: unlink makes its two neighbors point to each other. That's O(1).

remove(value) is still O(n), but only because it has to find the value. If you already have the node (or a std::list iterator), deleting it doesn't walk anything.

Removing at the ends: O(1) at the back too

This is the big difference from the singly linked list: to remove the last node, there you had to walk to the second to last. Here tail->prev already tells you. With the list empty, both functions throw out_of_range.

Extra memory per node1 pointer2 pointers
  • Use it when you add and remove a lot at both ends, or delete nodes you have already located.
  • An LRU cache (least recently used items go out first) combines a doubly linked list with a hash table: moving an item to the front is O(1).
  • A browser's back/forward history or an editor's undo/redo are walked in both directions.
  • To read by position or traverse a lot, std::vector is still faster and uses less memory.

Practice

  1. Write removeAt(int pos) using nodeAt and unlink.
  2. Write void reverse(): it's enough to swap prev and next in each node, and then head and tail.
  3. Write bool isPalindrome() const walking with two pointers, one from each end.
  4. Add moveToFront(int value): it finds the node and, without deleting it, hooks it in at the front (that's what an LRU cache does).
