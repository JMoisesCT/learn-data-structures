Circular list

A linked list where the last node, instead of pointing to nullptr, points to the first one. Great for handing out turns.

The last points to the first

Like a round of players: after the last one comes the first one again. Storing last is enough, because the first one is last->next: both ends in O(1).

There's no nullptr at the end: you walk it with do … while until you're back at the first one. Otherwise, the loop would go around forever.

Why does find use do … while and not while (current != last->next)?

insertAtFront: opening the ring and closing it

The new node slips in between the last and the first: it points to the one that is first right now, and the last one starts pointing to it. That's two pointers, O(1). If the list was empty, the only node points to itself.

After insertAtFront, did last change?

insertAtBack: inserting at the front and moving last

The front and the back are at the same spot in the ring: between the last and the first. The only difference is which node last points to. That's why inserting at the back is inserting at the front and moving last forward one node: O(1).

In a singly linked list with only head, inserting at the back cost…

rotate: the first one goes to the back without moving

In an array, moving the first element to the end forces you to shift all the others. Here it's enough to move last forward one node: the one that was first is now the last. No node moves in memory, just one pointer: O(1).

With 4 nodes, how many times do you have to call rotate() for everything to be as it was at the start?

removeFirst: the last one jumps to the second

The first one is last->next: to take it out, the last one starts pointing to the second one and the first one is freed. O(1). If it was the only node, the list is left empty (last = nullptr); if it was already empty, it throws out_of_range.

A real use: handing out turns

An operating system shares the processor among programs in turns (round-robin): each one works up to a time quantum; if it finishes, it leaves the round, and if not, it goes to the back. Each node stores how much work a process still needs.

With quantum = 3 and processes of 5, 3 and 7, which one finishes first?

All together

All the operations on the same ring. Notice that none of them walks the list, except find.

Complexity and where it's used

OperationTimeWhy
insertAtFront / insertAtBackO(1)Both ends are right next to last.
rotateO(1)It just moves last forward; the nodes don't move.
removeFirstO(1)The last one jumps to the second.
findO(n)One full lap with do … while.
Removing the last oneO(n)You have to find the second to last (with a circular doubly linked list, O(1)).
  • Turns: an operating system's process scheduler, the players of a turn-based game, a playlist on repeat.
  • Circular buffers: the same idea with an array (the indices wrap around with % capacity); that's how fixed-size queues are usually implemented.
  • The STL has no circular list, but you can imitate one with std::list and an iterator that goes back to begin() when it reaches end().
  • The Josephus problem is exactly a round: count, take one out and keep going.

Practice

  1. Write bool remove(int value). Hint: walk with a prev pointer that starts at last, and take care of the single-node case and of deleting the last one.
  2. Write int josephus(int n, int k): n people in a circle, you count k at a time and the one you land on leaves. Who is left?
  3. Change the list so it's circular and doubly linked (each node with prev). How much does removing the last one cost now?
  4. Write void printFrom(int value), which goes one full lap starting at that value.
