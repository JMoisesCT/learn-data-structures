Binary search

If the data is sorted, looking at the middle one is enough to discard half at once. With a million elements, 20 iterations are enough. You'll see the iterative and the recursive version, their traps, lower_bound and upper_bound, and how to search for an answer even when there's no array.

Guess by splitting in half

There are 16 cards sorted from smallest to largest, face down, and you have to find a number. Each card you turn over tells you whether the number is to its left or to its right: all the ones on the other side are out, without looking at them.

Play once your own way and then let the middle strategy play. Always picking the one in the center splits the candidates in half: 16 → 8 → 4 → 2 → 1.

With the middle strategy, how many cards do you have to turn over, at most, if there were 1024?

binarySearch: a box that shrinks

The candidates are between left and right. On each iteration v[mid] is checked: if it's the target, done; if it's smaller, the target can only be to the right (left = mid + 1); if it's larger, to the left (right = mid - 1). If left passes right, it isn't there: O(log n).

Why is the condition left <= right and not left < right?

The same idea, recursive

Instead of moving left and right, the function calls itself with the half that's left. There are two base cases: nobody is left (left > right) or the middle one is the target. Each call waits on the stack for the one below to return the result, and returns it as is.

And if the array isn't sorted?

Discarding a half without looking at it is only valid because the order guarantees the target isn't there. Without order, binary search doesn't fail with an error: it answers wrong, and returns -1 even if the value is there. You have to sort first (O(n log n)) or search one by one (O(n)).

You have an unsorted array and you're going to search for a single value. What's best?

The mid that overflows

Why left + (right - left) / 2 and not (left + right) / 2? They're equal in math, but an int only goes up to 2,147,483,647. With a huge array, left + right goes past it and wraps around to the negatives. This bug sat for years in the binary search of Java's library.

lowerBound and upperBound: with duplicates

lowerBound(v, x) looks for the first position with v[i] ≥ x: the first copy of x, or where it would go. upperBound looks for the first with v[i] > x. They don't stop when they see x: the answer is between left and right (including the end, v.size()) and they keep going until one is left.

Together they enclose all the copies of x: countOccurrences counts them with a subtraction, without walking through them. In the STL they're std::lower_bound, std::upper_bound and std::equal_range.

In {2, 4, 4, 4, 7}, what does lowerBound(v, 5) return?

Search for the answer, not an element

Binary search works with any question that answers yes, yes, …, yes, no, …, no. For the integer square root of n, the candidates are 0, 1, …, n and the question is "r · r ≤ n?". Each "yes" moves left and each "no" moves right: the last yes is the answer.

Complexity and when to use it

Linear searchstd::find (doesn't need order)O(n)O(1)
  • Use it when the data is already sorted and is queried much more than it changes: a sorted std::vector is compact and very fast to go through.
  • It needs O(1) access by index: it works on an array or vector, not on a linked list.
  • If you insert and delete often, keeping the vector sorted costs O(n) per operation: a binary search tree (std::set) does the same in O(log n). Each node plays the "mid".
  • If you only ask "is it there?" and the order doesn't matter, a hash table answers in O(1) on average.
  • Over the answer: roots, the minimum size that's enough, the first version that broke something (git bisect).
  • Watch the bounds: left <= right or left < right, mid - 1 or mid. Each version is consistent with itself; mixing them gives infinite loops.

Practice

  1. Write int lastOccurrence(const std::vector<int>& v, int x), which returns the last position of x or -1, using upperBound.
  2. Change right = mid - 1 to right = mid in binarySearch and search for a value that isn't there. What happens and why?
  3. Search in a sorted array that was rotated, like {27, 30, 34, 3, 8, 12, 15}, in O(log n). Hint: one of the two halves is always sorted.
  4. Search over the answer: given the weights of some packages in order and d days, find the minimum capacity of a truck that delivers them all in d trips.
